# 05 — API

The OpenAPI document generated by FastAPI (`/api/v1/openapi.json`) is the contract with the front end. The front end generates its TypeScript client from it, so naming and schemas matter.

## Conventions

| Topic | Rule |
| --- | --- |
| Base path | `/api/v1`. Additive changes only within v1 |
| Route definition | Every route: explicit `response_model`, unique `operation_id` (`get_tournament_standings`), one tag per module, summary line |
| JSON | `snake_case` fields; IDs as strings; timestamps ISO 8601 UTC with `Z`; money in cents as integers |
| Errors | Problem details (RFC 9457): `{"type","title","status","detail","code","errors":[{"field","message"}]}` |
| Status codes | 200, 201, 202, 204, 304; 400, 401, 402 (`premium_required`), 403, 404, 409, 422, 429; 5xx |
| Pagination | Cursor: `?cursor=&limit=` (default 20, max 100) → `{"items":[…],"next_cursor":"…"|null}` |
| Caching | `ETag` from read-model `version`; `If-None-Match` → 304. Anonymous data `Cache-Control: public, max-age=30` (live tournament pages `max-age=5`); personal data `private, no-store`. Anonymous public responses are also shared from Redis for their `max-age` (≤ 30 s), like a CDN |
| Idempotency | Scorer events by (`match_id`, `client_seq`). Other unsafe POSTs accept `Idempotency-Key` (stored 24 h) |
| Optimistic concurrency | Editable resources return `version`; updates require `If-Match`; stale → 409 `stale_version` |
| Rate limits | Auth, uploads, invites, search, scorer endpoints. 429 with `Retry-After` |
| Freshness | Read models include `computed_at`; live payloads include `server_time` |
| Language | `Accept-Language` or `?lang=` (`fi`, `en`, `bn`) selects content language when available |
| Identity | Cookie session (user), `Authorization: Pass <token>` (scorer pass), or none (public pages) |
| AI label | Every story/commentary payload has `author_type` and `ai_label` (localised text, e.g. "Written by AI from match data") |

### Standard error codes

`not_authenticated`, `forbidden`, `premium_required`, `not_found`, `validation_error`, `stale_version`, `conflict`, `seat_limit_reached`, `invite_expired`, `rules_not_confirmed`, `setup_not_ready`, `open_questions_remaining`, `processing_agreement_required`, `draw_infeasible`, `schedule_infeasible`, `filming_not_permitted`, `match_not_live`, `scorer_not_assigned`, `pass_revoked`, `pass_not_yet_valid` (a scorer pass before the tournament days), `rate_limited`, `upstream_unavailable`.

`GET /me` response:

```json
{ "id": "…", "display_name": "Aino K.", "email": "…", "language": "bn", "time_zone": "Asia/Dhaka",
  "plan": { "tier": "premium", "granted_by_organisation_id": "…", "valid_until": "2027-06-30T00:00:00Z" },
  "memberships": [ { "organisation_id": "…", "organisation_name": "FinBangla SC", "role": "admin" } ],
  "staff_tournaments": [ { "tournament_id": "…", "tournament_name": "FinBangla Cup 2026", "organisation_id": "…", "role": "owner" } ],
  "global_roles": [], "primary_team_id": "…", "family_player_ids": ["…"],
  "follows": [ { "id": "…", "target_type": "team", "target_id": "…", "is_primary": true } ],
  "unread_notifications": 3 }
```

Accounts may not call other modules, so the parts of `Me` they own are filled by contributors registered at start-up (`accounts.service.contribute_to_me`): competitions adds `memberships` (organisations whose processing terms the user accepted or whose tournaments they run) and `staff_tournaments`; audience adds `follows`, `primary_team_id` and `unread_notifications`.

**Stories (T-052):** `getTournamentStories` (`?lang=`), `getMatchStories` (`?kind=preview|report&lang=`), `getStory` (adds `sentences` and the `facts` they cite). Only published stories are served; every AI story has `author_type: "ai"` and a localised `ai_label`. Feed items of kind `result` carry `stories` (the match report in every language); the My Team hub's `stories` lists the team's recaps and its matches' stories.

**Front-end fields (T-066):** `TeamName` carries `short_name`; `MatchCard` carries `tournament_id`, `sport` and `data_level`; `TournamentPage` carries `organisation_id`, `organisation_name`, `is_junior` and `format {kind, qualify_per_group, best_of_rest, points, match_minutes, tiebreakers, standings_visible}` from the confirmed rules (`null` before; `qualify_per_group` is 0 when no knockout follows, the table decides); standings groups carry `group_id` and every row a `status` (`through`, `out`, `alive`, from the scenarios read model); `TeamPage` carries `organisation_id`, `age_group` and the `players` this viewer may see (so a signed-in team page is never shared from the cache); `StoryOut` carries `tournament_id`. `GET /players/{id}` (`getPlayer`) answers 404 to anyone the visibility rules hide the player from.

**Implementation (T-033):** fan reads live in `analysis.router` (analysis may read scoring's live state and its own snapshots); organisation and series pages in `competitions.router`; the published draw in `setup.router`. ETags are a hash of the response body (`app/core/http_cache.py`). Live access: `public` everyone; `members` any signed-in user for now (followers and organisation members from T-040); `premium` staff only until subscriptions. Timelines never carry player ids. Scenarios drop shares when `show_probabilities` is false.

**Legal and consent (T-061):** `GET /legal/{document}?lang=` (`getLegalDocument`); `GET /me` and `PATCH /me` carry `preferences` (`analytics_cookies`, `marketing_emails`); `publishSetup` takes `{filming_policy}`; reports take `kind`; `unpublishStory` needs `{reason}`; `GET /me/reports` (`listMyReports`).

**Implementation (T-054):**
- Operations: `listReviewQueue` (`?reason=blocked_claim|sensitive`), `takeNextReview`, `getReviewItem`, `claimReview` (409 when another editor has it), `editStory` (If-Match: the story version; 409 `stale_version`), `checkStory`, `approveStory`, `rejectStory`, `unpublishStory`, `regenerateStory`, `listCorrections` (`?status=`, default `open`; each report carries `story_headline` and `story_status`), `resolveCorrection` and `listEditorStories` (published or unpublished stories, latest change first, at most 200; `ReviewSummary` carries `reviewed_by_editor` and `removal_reason`).
- Every editor endpoint needs the global role `editor`; anyone else gets 404.
- Readers report mistakes with `POST /stories/{id}/corrections` (`reportCorrection`, member).
- An approved story keeps the AI label with ", reviewed by an editor" (localised).
- Organisers correct a finished match by posting events to it (`postMatchEvent` / `undoMatchEvent`; scorer passes cannot). The result is recomputed from the events; scoring sends a `correction` live message with the new `result`. The re-analysed report is rewritten with `corrected_at`, and a `correction` message with `story_corrected` goes to the match and tournament channels.

## Key response schemas (summary)

- **SetupSession:** `SetupOut` also carries `tournament {name, organisation_id, sport, age_group, is_junior, time_zone, starts_on, ends_on}`. `{id, status, progress:{step, percent}, summary, draft:{rules, format, seeding, schedule_policy, teams}, assumptions:[{id, field, chosen, reason, alternatives}], open_questions:[{id, field, text, quotes, options, impact, ref}] (`ref.issue` marks an engine validation issue), draw:{groups, pots, reasons, seed}, schedule:{days:[{date, pitches:[{pitch, matches}]}], quality}, version}`
- **StandingsGroup:** `{group_id, group_name, version, computed_at, tiebreak_label, rows:[{position, team, played, won, drawn, lost, no_result, points, score_diff, tiebreak_value, form, status, decided_by}]}`
- **Bracket:** `{version, rounds:[{stage, matches:[{code, home:{team|null, source, could_be}, away:{…}, result, starts_at, pitch}]}]}`
- **Scenario:** see `04-engine.md` + `text`, `fact_ids`.
- **Prediction:** `{match_id, show_percentages, home_win, draw, away_win, confidence, factors:[{id, kind, team, text}], computed_at}` — percentages null when hidden.
- **Comparison**, **MatchAnalysis**, **TimelineItem**: as before (`{seq, type: "event"|"commentary"|"correction"|"announcement", data, created_at}`).
- **Story:** `{id, kind, language, headline, body, label, author_type, ai_label, published_at, corrected_at, facts:[{id, claim}]}`
- **MyTeamHub:** see `14-personal-experience.md`.
